1. Rama de referencia única: `main` en GitHub (`Jadiaza/ao-erp`).
2. Al iniciar jornada en oficina o en casa:
   - Verificar rama `main` y ejecutar `git pull origin main`.
   - Si hay nuevas migraciones SQL en Git, aplicarlas en el PostgreSQL local independiente de ese computador.
3. Desarrollo local:
   - Trabajar contra la base PostgreSQL local independiente (sin compartir carpeta de datos por nube/OneDrive/Dropbox).
   - Mantener `.env` y respaldos `.dump`/`.sql` locales fuera de Git (`.gitignore`).
4. Antes de consolidar cambios a GitHub:
   - Ejecutar `bun run test:saas`, `bun run test:erp`, `bun run test:diocesano`, `typecheck` y `build`.
   - Crear commits descriptivos (sin secretos) y subir con `git push origin main` (nunca `--force`).
5. Traslado de datos entre oficina y casa (cuando sea necesario):
   - Exportar con `pg_dump` en origen -> verificar tamaño/integridad -> transferir de forma segura -> respaldar base destino antes de sobrescribir -> restaurar con `pg_restore` -> validar integridad.
